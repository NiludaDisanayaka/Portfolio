A systems habit, wherever it starts

My coursework spans computer science, physics, and chemistry, and I've noticed the same instinct shows up in all three: figure out the constraints first, then build something that respects them.

That instinct doesn't stay on the screen. Before I built a ring-toss game as a physical build, I calculated the cone dimensions by hand for each difficulty level — geometry doing the design work before a single piece of wood got cut. I bring the same habit to software: understand the shape of the problem, then write code that fits it.
